# GitHub Integration

Reflex.md ships as a **GitHub App** (not an OAuth App). This gets us:

- **Installation tokens** — per-repo, short-lived, scoped. No user PATs to manage.
- **Per-repo permissions** — user picks which repos Reflex can touch at install time.
- **Webhook delivery** — push, pull_request events flow in with signed payloads.

## Permissions (minimum viable)

| Scope | Access | Why |
|---|---|---|
| Repository → Contents | Read & write | Clone shadow branch; write `AGENTS.md` / `CLAUDE.md` on a PR branch. |
| Repository → Pull requests | Write | Open PRs. |
| Repository → Metadata | Read | Enumerate default branch, branch list (to check for `entire/checkpoints/v1`). |

**Webhooks subscribed:**
- `installation` — handle install/uninstall.
- `push` — detect new checkpoints on `entire/checkpoints/v1` (MVP: informational; auto-ingest is v2).
- `pull_request` — detect merge/close of Reflex PRs to update proposal status.

## Install / onboarding flow

```
┌──────────┐    1. Click "Install on GitHub"
│  Landing │───────────────────────────────────►  github.com/apps/reflex-md/installations/new
└──────────┘
                                                      │
                                                      ▼ user picks repos
┌──────────────┐  2. GitHub redirect w/ installation_id + setup_action
│  /onboarding │◄─────────────────────────────────────
└──────────────┘
       │ 3. exchange installation_id → installation access token
       ▼
┌──────────────┐  4. list accessible repos, user picks one
│  /repos      │
└──────────────┘
       │ 5. verify repo has `entire/checkpoints/v1`
       │    (GET /repos/{owner}/{name}/branches/entire%2Fcheckpoints%2Fv1)
       │
       ├── missing? → CTA: "Install entire-cli first" with docs link
       └── present? → enqueue first ingest + analysis → redirect to Timeline
```

### Authentication

- We never store the user's GitHub password or a user PAT.
- **Login** = "Sign in with GitHub" over GitHub's OAuth — but only to identify the human. Repo access is via the **installation** token, not the user token.
- Installation tokens are minted per-request, cached for ≤ 50 min, never written to disk.

## Cloning the shadow branch

Two options; pick based on repo size:

1. **Shallow clone (default):**
   ```
   git clone --filter=blob:none --no-checkout --depth=1 \
     --branch entire/checkpoints/v1 \
     https://x-access-token:<token>@github.com/<owner>/<name>.git
   ```
   Then `git sparse-checkout` only the checkpoint shards we need.

2. **API-only walk (for tiny test repos):**
   Walk `GET /repos/{o}/{r}/contents/{path}?ref=entire/checkpoints/v1`. Rate-limit-heavy; only used in tests.

The clone goes into a per-repo temp dir, wiped after ingest. No long-lived working tree.

## PR creation contract

Input: the approved `ProposedEdit` from [`ANALYSIS_ENGINE.md`](./ANALYSIS_ENGINE.md).

Steps:

1. Create branch `reflex/update-<targetFile>-<shortAnalysisId>` from the repo's default branch (via Git Data API: get ref → get commit → get tree → create blob → create tree → create commit → create ref).
2. Open PR:
   - **Title:** `Reflex: update <targetFile> — <top cluster representativeText>`
   - **Base:** default branch
   - **Head:** the new branch
   - **Body:** see template below.
3. Store `PullRequest{ analysisId, githubPrNumber, status: 'open' }`.

## Webhooks

All webhook payloads verified with `X-Hub-Signature-256` against the app's webhook secret. Invalid → 401.

| Event | Action |
|---|---|
| `installation.created` | Create/update `User` + `Installation` rows. |
| `installation.deleted` | Soft-delete user's repos. |
| `installation_repositories.added/removed` | Sync `Repo` rows. |
| `push` on `entire/checkpoints/v1` | v1: log only. v2: auto-enqueue ingest. |
| `pull_request.closed` with `merged=true` on a Reflex branch | Mark `PullRequest.status = 'merged'`, bump `Pattern.supportCount`. |
| `pull_request.closed` with `merged=false` | Mark `status = 'closed'`. |

## Rate limits

- Per-installation GitHub API limit is generous (5000/hr) but cloning bypasses REST.
- Sustained ingest strategy: **clone once, walk locally**. Never walk via `contents` API outside tests.
- Probot handles webhook throttling natively; we piggyback.

## Local dev

- Use [`smee.io`](https://smee.io) for webhook forwarding.
- A **development GitHub App** separate from production (own App ID, own private key, own webhook secret).
- `.env.example` lists: `GITHUB_APP_ID`, `GITHUB_APP_PRIVATE_KEY` (PEM, base64), `GITHUB_APP_CLIENT_ID`, `GITHUB_APP_CLIENT_SECRET`, `GITHUB_APP_WEBHOOK_SECRET`.
